# Phase 05 Plan 01: Voice Changer

## Goal

Make the Voice Changer mode real: a person speaks Vietnamese, and Vietnamese
comes out in another person's voice — from a file into a Take, and live from a
microphone into a device.

The engine survey lives in `.planning/research/VOICE-CONVERSION-ENGINES.md`. This
plan decides what to do with it.

## Why this is not generation with a trained set

A Voice Model Set (plan 03-03) generates speech **from text**. A changer keeps
the performer's timing, breath, emphasis and emotion, and replaces only the
timbre. Two consequences follow:

- **Emotion comes from the performer**, so a changer needs no per-emotion
  adapters. The target is one voice, not a set.
- **The target is a Voice Model in the `CONTEXT.md` sense** — "a trained
  checkpoint or reference-based voice artifact" — and never a Voice Model Set.
  It has two kinds:

| Kind | What it is | Comes from |
| --- | --- | --- |
| `reference-clip` | A few seconds of the target speaker, used zero-shot | The Voice Model Set's anchor slice, or an approved Media Pool span, recorded by asset id, span and hash |
| `vc-checkpoint` | A conversion model trained for one speaker | A Training Run over the same Dataset Manifest 03-02 compiles, audio only |

A Speaker Profile that already has a Dataset Manifest therefore gets both kinds
without recording anything new.

## Preconditions

- Phase 03 is complete, including the `SpeakerEmbedder` port (03-03 task 10) —
  the similarity measurement below uses it.
- The single GPU lease from 03-03 exists and is honoured by every workload.
- Phase 04's `WorkspaceSession` exists before the live stream is built: moving
  the Control Rack must not stop a stream any more than it may stop a recording.
- Plan 07-01's `ModelStore` ports exist; each engine runtime and model is a
  `ModelDescriptor` with its licence.

Tasks 1–3 touch no product code and could run before Phase 04. Whether they do
is the owner's sequencing call, not this plan's.

### This machine

`nvidia-smi` on 2026-09-13: one RTX 3090, 24 GB, 2.4 GB in use. Every latency and
RTF number in this plan is measured here and says so; a paper's number is never
reported as ours.

## The Vietnamese gate

No engine becomes a product feature until it passes this on real project audio.
Thresholds are stated first, measured second, and declining an engine is an
acceptable result (the R5 pattern). The numbers below are **provisional until
the owner confirms them**, and must be confirmed before the measurement runs, not
after.

### Test set

- Guided-reading takes from 03-04 first: their text is ground truth, not a
  recogniser's guess. Top up with Media Pool footage whose Script is
  user-corrected.
- At least 40 utterances from two source speakers, converted to two targets,
  one pair crossing gender — the pair that stresses pitch handling most.
- Frozen as a manifest with hashes, so a re-run measures the same audio.

### Measurements

| # | Question | Measured how | Provisional gate |
| --- | --- | --- | --- |
| 1 | Are the words still the words? | Finalized Faster-Whisper, same settings as STT, on source and on output; CER on diacritised text against ground truth | Output CER no more than **3 points** worse than source CER |
| 2 | Did the tones survive? | Per-utterance F0 contour correlation, source vs output, voiced frames only | Reported, no gate on first run |
| 3 | Does it sound like the target? | `SpeakerEmbedder` similarity to the target reference | Must sit closer to the target's own second clip (ceiling) than to the source speaker (floor); no absolute number invented |
| 4 | How fast, here? | RTF on GPU and on CPU; live end-to-end latency by loopback impulse | See latency budget |
| 5 | Would a listener accept it? | Owner blind A/B, source vs each engine, ten utterances | Owner's call |

Gate 1 carries the tone question because a tone error changes the word. Its
weakness is that the recogniser's language model can repair a wrong tone from
context, which is why measurement 2 is reported and measurement 5 stays.

### Latency budget

| Use | Who hears the output | Budget |
| --- | --- | --- |
| File conversion | Nobody live | None; report RTF |
| Live to a call, stream or recording | Listeners | **≤ 300 ms** target, 500 ms hard limit, end to end |
| Performer monitoring their converted voice | The performer | Not offered by default |

The last row is deliberate. Hearing your own voice back with a delay disturbs
fluent speech (delayed auditory feedback), and no engine here reaches the few
tens of milliseconds that would avoid it. Monitoring converted output is an
explicit toggle that says why it is off.

Latency is **measured, not summed from settings**: an impulse played into the
input device and detected at the output, repeated, reported as median and p95.

## Live audio: native loop, not a browser loop

Two ways to move live audio exist:

- **Browser loop** — AudioWorklet capture, PCM over WebSocket to the sidecar,
  converted PCM back, Web Audio out. Reuses Recorder, but stacks the browser's
  input and output buffering on top of the engine, requires disabling Chrome's
  echo cancellation and gain control, and throttles when the tab is hidden.
- **Native loop** — the sidecar opens the input and output devices itself
  through PortAudio (WASAPI, or ASIO where present). The browser is only a
  control surface: device choice, target, start/stop, meters.

**Decision: native loop.** Latency is the whole point of the live mode, and the
browser's buffers are the one part of the budget we cannot tune. It also keeps
streaming when the tab is backgrounded and carries straight into the Tauri shell
of Phase 07. Recorder's browser capture stays exactly as it is for recording.

Two consequences stated plainly:

- **The devices are the sidecar machine's.** Over remote access, a remote
  browser's microphone is not the input. Remote live conversion is out of scope.
- **Sending converted voice to Zoom, Discord or OBS needs a virtual audio
  device** such as VB-CABLE. It is a driver; like the NVIDIA driver in 07-01,
  only the user can install it. A preflight detects one and says what to do if
  none is found.

## Process shape

**One port, two surfaces.** File conversion and live conversion call the same
engine through one `VoiceConverter` port:

```
VoiceTarget        reference-clip(asset_id, span, sha256) | vc-checkpoint(voice_model_id)
ConverterCaps      kinds, streaming, min_chunk_ms, lookahead_ms, devices, sample_rate,
                   duration_preserving, pitch_shift
VoiceConverter     capabilities() -> ConverterCaps
                   prepare(target) -> PreparedTarget
                   convert_file(source, target, settings, on_progress) -> Path
                   open_stream(target, settings) -> ConversionStream
ConversionStream   process(block) -> block;  close()
```

**Each engine gets its own runtime.** RVC's fairseq pins, MeanVC2 and Seed-VC do
not share a torch version with each other or with OmniVoice. Each is a pinned,
read-only upstream checkout — the ADR 0001 rule, unchanged — with its own venv,
provisioned as a visible, resumable step as in 03-03 task 1, and never
committed.

**The live stream runs in a sidecar, inside the launcher's Job Object.** A CUDA
error must not take down the API, and a closed app must not leave a process
holding the microphone or the GPU.

**The streamer is ours and engine-agnostic.** Block size, crossfade/SOLA overlap,
a silence gate so silence passes as silence rather than as engine noise, and
dropout accounting that reports underruns as a count, never hides them.

**The GPU lease decides, and training wins.** A live session acquires the lease
for its whole duration. If a Training Run holds it, the session offers a CPU
engine when one passed the gate, and otherwise refuses with the reason. It never
preempts a run that has been going for hours.

## Outputs and lineage

**File conversion produces a Take** under `assets/media/<asset-id>/`, with
`origin: conversion` and lineage recording the source asset and span, the
`VoiceTarget`, engine id and revision, model hash, settings (pitch shift, chunk,
index rate) and the output sample rate. Output keeps the engine's native rate;
nothing is silently upsampled to claim bandwidth it does not have.

**Word timing is inherited only when it is safe.** The Take copies the source's
Script and Source Word Timing only when the engine declares
`duration_preserving` **and** the measured output duration matches the source
within one frame. Otherwise the Take goes through STT like any other audio —
word timing that is merely assumed is exactly what ADR 0007 forbids.

**A live session may record.** When enabled, input and converted output are
written as two linked Takes, and `jobs/live-conversion/<session-id>/session.json`
keeps the target, engine, settings, measured latency and underrun count.

## Open decisions for the owner

1. **Consent.** 07-01 already calls a trained voice "a working impersonation of a
   real person", and a live changer is the most direct form of that the product
   would have. Recommendation: a Voice Changer target must be a Speaker Profile
   carrying a consent attestation, and an arbitrary uploaded clip is not a
   target.
2. **Seed-VC.** Benchmark only (recommended), or accept GPL-3.0 on an archived
   project to ship it.
3. **MeanVC2 licence.** Wait for a LICENSE file upstream (recommended) or rely on
   the README badge.
4. **The provisional gate numbers** above, before task 3 runs.

## Tasks

1. Build the evaluation runner outside `engines/`: frozen test-set manifest,
   CER through the existing STT, F0 correlation, `SpeakerEmbedder` similarity,
   RTF, and a report that records machine, engine revision and model hash.
2. Provision isolated runtimes for RVC, MeanVC2 and Seed-VC as visible,
   resumable steps. Seed-VC's runtime is marked benchmark-only and never
   registered in the `ModelCatalog`.
3. Run the gate on this machine and record the numbers with their evidence. The
   owner decides which engines proceed; a declined engine gets no adapter.
4. Add `VoiceTarget`, `ConverterCaps`, `VoiceConverter` and `ConversionStream`,
   with adapters only for engines that passed.
5. File conversion as a `WorkflowCoordinator` job: progress in seconds of audio
   converted, cancel, a Take with full lineage, and the word-timing inheritance
   rule.
6. If RVC passed: an RVC `TrainingRunner` adapter consuming a Dataset Manifest's
   audio, publishing a `vc-checkpoint` Voice Model with manifest hash and engine
   revision.
7. Live conversion sidecar: native device I/O, the streamer, silence gate,
   underrun count, GPU lease with CPU fallback, and every child in the Job
   Object.
8. Loopback latency measurement, and a preflight for devices, virtual cable and
   lease state that says what it found and what to change.
9. Control Rack for Voice Changer: target picker (profile → reference clip or
   trained model), engine picker filtered by capability and lease, pitch shift,
   chunk size with the **measured** latency beside it, backend device lists,
   record toggle, monitoring toggle off by default.
10. Remove `voice-changer` from `plannedModes` only once verification below
    passes — until then MAN-03's honest planned state stands.
11. Tests: test-set manifest determinism, lineage completeness, word-timing
    inheritance accepted and refused, lease contention with a mock training run,
    streamer crossfade continuity and underrun counting against recorded blocks,
    capability filtering in Control Rack.

## Verification

- Converting a Media Pool asset produces a Take that plays from its project-owned
  path, and its lineage names source, target, engine revision, model hash and
  settings.
- Every evaluated engine has recorded gate numbers with evidence; a declined one
  has no adapter and no UI entry.
- A live session's displayed latency is the loopback measurement, and underruns
  appear as a count rather than as silent glitches.
- Starting a live session during training offers CPU or refuses with a reason;
  training neither slows nor runs out of memory.
- Killing the app mid-session leaves nothing holding the microphone or the GPU.
- Moving the Control Rack while a stream runs does not interrupt it.
- A Take whose duration drifted does not inherit word timing.

## Not in this plan

- Cross-lingual conversion. Changing language is Voice Dubber.
- Singing voice conversion.
- Emotion or style transformation; the performer's delivery is kept.
- Audio watermarking of converted output.
- Live conversion from a remote browser's microphone.
- Installing or bundling a virtual audio driver.
- LLVC and Beatrice v2 adapters.
- Any edit inside an upstream engine checkout.
