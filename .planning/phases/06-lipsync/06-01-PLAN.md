# Plan 06-01: LipSync Page And Adapter Contract

## Steps

1. Register `lip-sync`, its six-zone default manifest, module definitions, and route tests on the Phase 04 dock shell.
2. Extend assets/takes with video/audio eligibility, approval status, derivative lineage, and project-relative output placement.
3. Create backend `LipSyncAdapter` request/result/error schemas and a persisted job lifecycle with cancellation, progress, diagnostics, retry eligibility, and Media Pool insertion.
4. Implement Video Preview, ShotFaceMap review, LipSync Rack input validation, and Render Queue/Recent Renders through `WorkspaceSession`.
5. Evaluate candidate engine/model reproducibility, licensing, GPU memory, visual quality, identity preservation, and output compliance before enabling actual rendering.
6. Add integration and negative-path tests: missing video, missing approved audio, no face, multi-face confirmation, canceled job, invalid output, and moved-project reopen.

## Acceptance evidence

- A fixed evaluation reel has visual/audio QC records, engine/model revision, GPU usage, known artifacts, and a human approval decision.
- Every emitted asset is decodable, duration-checked, project-relative, and has source/take/shot-map/engine/settings lineage.
- No action reports a rendered result when the adapter or QC validation has failed.

## Follow-on

Production model download occurs only after the candidate passes this gate and is entered in the machine-local model registry. Its repository and model weights remain replaceable adapter dependencies.
