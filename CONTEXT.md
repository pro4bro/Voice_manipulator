# Domain Glossary

- **Subtitle Alignment Proposal**: A reviewable set of word-boundary changes for one finalized footage or audio track, bound to its current Script and immutable audio. It preserves manual timing, original provenance and uncertain words; an applied proposal has a reversible input snapshot.
- **Subtitle Drift Report**: Read-only evidence comparing current word timing with qualified acoustic coordinates, including manual words. Displacement, quiet or invalid spans identify places to listen again; unassessed words and CTC uncertainty remain explicit, and the report cannot apply changes.
- **Subtitle Timing Ghost**: A transient Timeline overlay of changed word coordinates computed from enabled refinement methods and a bound source snapshot. Ghost Preview never saves timing; Apply New Timing commits its valid changes together. Explicitly retained overlap remains visible as a timing conflict, including after reopen.

- **Project**: A portable folder containing one voice production effort, its manifest, assets, activity, notes, jobs, exports, cache, and last workspace state.
- **Asset**: An immutable audio or transcript input/output with provenance.
- **Take**: A playable audio Asset created by recording, generation, conversion, dubbing, or patching.
- **Capture Tier**: How an Asset's audio and transcript came to exist — `guided`, `record`, or `import`. It is provenance, not a quality score, and an Asset written before the field existed derives it from its origin.
- **Capture Check**: The pre-flight measurement of one recording chain — peak headroom, noise floor, clipping — stored with the Reading Session that measured it.
- **Speaker Profile**: A human identity in one Project, described by name, language, region, age, and gender. Footage and Script words may reference it before any model exists.
- **Voice Model**: One addressable, project-owned voice artifact for a Speaker Profile: a reference clone, LoRA, full checkpoint, or voice-conversion model. The implementation record is currently named `ProjectVoice`; one Voice Model is usable on its own but is not proof that a coordinated set passed identity validation.
- **Voice Model Set**: The publication aggregate for one Speaker Profile: one identity anchor, one compatible generation family, its neutral/per-emotion Voice Models, reproducible dataset/engine/config lineage, and identity-gate evidence. A set publishes and is selected as a unit when generation may switch emotion; unrelated Voice Models must never be mixed into it.
- **Voice Collection**: A named host-local archive of trained Voice Models copied from Projects, with common Speaker classification properties. Each entry retains its Speaker Profile, required artifacts, consent evidence and verified training/publication lineage. Import copies the entry into a destination Project; a collection does not replace a Voice Model Set or grant publication rights.
- **Speaker Diarization**: Assigning time-aware speech spans to `Diarization Speaker` labels; it answers who spoke when but does not produce isolated audio. A user can then map each label to a Speaker Profile.
- **Diarization Speaker**: A processor-generated, time-aware label such as `Speaker 1` or `Speaker 2`; it is distinct from a Speaker Profile and may be mapped to one after review.
- **Voice Isolation**: Producing separate voice stems from mixed audio. Isolation output may then be diarized and annotated.
- **Emotion Label**: Controlled delivery/psychological context attached to a whole footage Asset or individual Script words. `mix` means the Asset contains more than one word-level label.
- **Environment Noise Profile**: A named reusable model of ambient sound learned from multiple audio Assets; it is distinct from destructive denoising.
- **Training Catalog**: Project-owned aggregate containing Speaker Profiles, Environment Noise Profiles, and Training Settings.
- **Footage Tag Menu**: The Media Pool right-click menu used to assign file-level Speaker Profiles and one Emotion Label without permanently expanding every footage row.
- **Reading Pack**: App-level, read-only reading material for one language — passages of Reading Cards, each passage carrying one Emotion Label and a delivery direction. A pack is an application resource, never project data.
- **Reading Card**: One utterance in a Reading Pack, intended to be read in a single breath and to become one training sample.
- **Reading Session**: A project-owned guided capture run pairing one Speaker Profile with selected passages, holding its takes, quality results, and per-emotion coverage. It snapshots the cards it recorded, so a moved Project keeps its own ground truth.
- **Dataset Manifest**: A deterministic, portable snapshot of selected audio segments, verified text, timing, speaker, and emotion attribution that a Training Run consumes.
- **Training Run**: One job that may fine-tune multiple Speaker Profiles and emits periodic checkpoint backups.
- **Workflow Step**: One named transformation stage that consumes Assets and may produce new Assets.
- **Workspace Page**: Dashboard, Input (Speech to Text), Voice Training, Voice Manipulator, Voice Changer, or LipSync.
- **LipSync Alignment Draft**: Session-only placement of one Media Pool video and one generated Voice Output on a shared preview clock; source IN points and timeline starts do not modify either Asset or imply a rendered derivative.
- **LipSync Session**: One independent video product within a Project, listed in Video Output, containing Version slots and sharing the Project's Media Pool and generated Voice Outputs.
- **LipSync Version**: One editable slot within a LipSync Session, owning its composition, face-review drafts, bounded Undo/Redo history and processing jobs. New version clones editing decisions and completed analysis, starts a separate history, and references the same immutable source assets.
- **Send to**: A source-routing action that opens a compatible workspace or stages shared footage/Voice Output references for a selected LipSync Version; it does not implicitly convert generated speech into Training footage.
- **LipSync Composition**: A revisioned project-owned arrangement of immutable video source spans on ordered layers and a generated audio placement, with engine settings and processing scopes. It supersedes the session-only alignment draft; it is not a rendered video.
- **LipSync Processing Scope**: An independent selection for detection or lip synchronization: chosen layers, an optional range, and visible, placed or full-source coverage. Source mode uses source time; other modes use composition time.
- **LipSync Preflight**: A saved-input snapshot of source coverage, generated speaker-turn intersections, native engine settings and unresolved blockers. It is not proof of detected identities or successful inference.
- **LipSync Face Observation**: A detected face at one sampled source time, with a thumbnail, embedding and proposed Face ID. A proposal is unreviewed until explicitly accepted; it is not a Speaker Profile.
- **LipSync Face Review**: A revisioned project-owned correction of observation IDs and explicit bindings from reviewed Face IDs to existing Speaker Profiles. Each analysis is a separate snapshot; new analyses currently need another review.
- **LipSync Render Job**: A durable snapshot of composition, reviewed identities, generated speaker turns, settings and immutable input fingerprints. Its completion requires decoded output artifacts; structural QC does not establish mouth/identity quality acceptance.
- **Manipulator Mode**: Voice Over, Voice Isolator, Voice Changer, Voice Dubber, or Voice Patch.
- **Script**: The time-aware transcript document shown and edited in the Script module.
- **OBS LiveLink Connection**: One OBS process's machine-local link and control state; it can be active while app recording is idle.
- **OBS LiveLink Channel**: One stable channel ID paired with an OBS source UUID. Its native source name, relay label, slot, and forwarding state can change without changing identity.
- **OBS Capture Recording**: One project-owned app audio recording spanning any number of OBS LiveLink channels and zero or more OBS video recording spans. Each completed recording becomes exactly one OBS Capture Footage.
- **OBS Capture Footage**: One Media Pool item for one completed OBS Capture Recording. Its source is a multitrack MKA; channel analysis WAVs and channel transcripts belong to this footage rather than appearing as separate footage.
- **OBS Video Recording Span**: One observed OBS Start-to-Stop video interval. It remains separate from the app recording and may later link to an imported MKV asset.
- **Project Target Lease**: A short-lived, machine-local claim by one workspace/project owner to receive new OBS LiveLink recordings.
- **OBS Source Archive**: The app's audio-only MKA parent asset with one independently addressable FLAC/PCM track per OBS source. Analysis WAV files are rebuildable derivatives for STT.
- **Imported Multitrack Footage**: One imported MKV, MOV, or MP4 source with two or more audio streams. The Media Pool shows one parent footage; each audio stream has a child analysis asset identified by its container stream index. A track is not proof of an isolated source or speaker.
- **Growing MKV Follow**: One native file locator feeding an Imported Multitrack Footage while its MKV grows. Complete Clusters and a durable per-track cursor produce provisional audio; an explicit Finish replaces it with continuously decoded audio from the closed, project-owned MKV.
- **OBS Overlap Review Interval**: A derived intersection of two or more different LiveLink channels on one recording's OBS time axis. It marks segment-level review and replay, not verified words or speaker identities.
- **OBS Overlap Selection**: Transient workspace focus on one review interval and its participating LiveLink channels or archived track assets. Script and Timeline share it; it does not alter the source or transcript.
- **Transcript Candidate**: A realtime, accurate STT, AI-corrected, or user-corrected option for one Script span.
- **Source Word Timing**: A per-word start/end interval returned by the STT recognizer. It remains the recognizer’s source data and is not a guessed replacement for alignment.
- **Timing Quality**: The Asset-level summary of word timing trust: `source` means every word is trusted, `partial` means fewer than 5% need individual alignment, `needs-alignment` means at least 5% are unsafe, and `unverified` has not yet been checked.
- **Word Timing Trust**: Whether one Source Word Timing interval passes structural checks. An untrusted word remains visible for review but is excluded from any subtitle cue that contains it.
- **Module**: A reusable deep UI or backend capability with a small interface and hidden implementation.
- **Engine**: An upstream AI implementation such as OmniVoice.
- **Base Model**: Weights that are identical bytes for everyone — an engine's checkpoint, a recognizer, a diarizer. Machine-local and shared by every project, downloaded on demand and verified by hash; never project content, because a project would otherwise carry gigabytes and lose portability.
- **Adapter**: In model terms, the small per-speaker weights produced by training here (tens of MB). User-owned, portable, and stored with the project or the Voice Vault — the opposite of a Base Model on every axis. Distinct from the code sense of adapter, which is Pro4Bro code at an engine seam.
- **Principal**: Who is acting on a request. Today there is exactly one and it is the machine's owner; the concept exists so identity has somewhere to attach before a second user arrives.
- **Adapter**: Pro4Bro code satisfying an interface at the seam between the app and an Engine.
- **Project Manifest**: Portable `project.json`; `projectPath` and `location` are `.` on disk and become resolved runtime paths only in memory/API responses.
- **Recent Registry**: Disposable app-level index pointing to project manifests; it can be rebuilt with Open Existing.

- **Reference Footage**: A project Asset chosen as an example of timing, delivery, volume, or emotion while the target character retains its own voice identity.
- **Reference Binding**: An association between one production selection and specific regions and qualities of one or more Reference Footage.
- **Timing Template**: The duration, pauses, rhythm and available word anchors of a source region, including how reliably those anchors map to the target text.
- **Duration Budget**: The time allotted to a clip, segment or sentence, including pauses within that unit; it is distinct from speaking speed.
