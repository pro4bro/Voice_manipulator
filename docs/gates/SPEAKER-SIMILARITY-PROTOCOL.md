# Speaker Similarity Gate Protocol v1

Status: implemented, threshold calibration pending.

## Decision Contract

Each member of a Voice Model Set must provide one project-owned Voice Output
generated by that exact Voice Model. The common reference is the set anchor
voice's trusted reference WAV. The gate:

1. accepts 16-bit PCM WAV only;
2. downmixes to mono and resamples to 16 kHz in memory;
3. rejects clips shorter than 3 seconds;
4. extracts one whole-window embedding per clip;
5. records cosine similarity for every member;
6. requires every score to meet that embedder's threshold;
7. publishes only when the threshold is marked calibrated.

Missing outputs, mismatched voice/output lineage, invalid/non-finite scores, an
unavailable model, or an uncalibrated threshold all fail closed. Evidence stores
the model ID and revision, threshold, calibration flag, protocol, score per
voice, and candidate Voice Output IDs.

## Source Basis

- The official [pyannote WeSpeaker model card](https://huggingface.co/pyannote/wespeaker-voxceleb-resnet34-LM)
  specifies `Model.from_pretrained`, `Inference(..., window="whole")`, and cosine
  distance between the resulting embeddings.
- The official [pyannote embedding model card](https://huggingface.co/pyannote/embedding)
  documents the same whole-window/cosine protocol and reports evaluation without
  VAD or PLDA; it does not publish a product threshold for this Vietnamese use.
- The official [WeSpeaker pretrained-model documentation](https://github.com/wenet-e2e/wespeaker/blob/master/docs/pretrained.md)
  states that LM models are intended to improve performance on audio longer than
  three seconds. Protocol v1 therefore uses three seconds as its hard minimum.

runtime connectivity only; it is not calibration and does not satisfy the real
