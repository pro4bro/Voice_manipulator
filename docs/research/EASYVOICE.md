Inspected 2026-10-12. Repository: [XavierChuu/EasyVoice](https://github.com/XavierChuu/EasyVoice). `main` HEAD: `af299a5cce44c6f877047bff54496fc1a823c090` (2026-10-09). Tag `v0.1.0`: `8ad0b49a2b2fb3a1e25070224c1af64b00a06622` (2026-10-09). The tag-to-main diff contains README/license/NOTICE/packaging and image changes, not feature-code changes. Findings below describe source presence and project claims; no installer or model-quality acceptance was run.

## What the app does

Evoice is a local-first Electron + React desktop shell backed by a Python/FastAPI engine. The README claims first-run downloads, after which it works offline; it advertises Windows and macOS installers, English/Vietnamese UI, auto-update, and bundled FFmpeg. The engine is localhost-only with a token according to its README. [README](https://github.com/XavierChuu/EasyVoice/blob/af299a5cce44c6f877047bff54496fc1a823c090/README.md) · [engine README](https://github.com/XavierChuu/EasyVoice/blob/af299a5cce44c6f877047bff54496fc1a823c090/engine/README.md)

| Product area | What README advertises | Source evidence in `main` |
|---|---|---|
| Voice library | Quick voice from a 5–12 second reference; high-quality RVC voice trained from 10–30 minutes; tags, emotion variants and `.evoice` sharing/import | Voice store, quick creation, RVC training pipeline, variant add/delete and `.evoice` export/import APIs exist. Engine README describes checkpoint pause/resume and scanning/rejecting unsafe imported files. |
| TTS | F5-TTS; sentence-wise render/re-render; speed, pauses, text normalization/dictionary; different voice per selected passage; direct and RVC chained modes | Engine has F5 backend/pipeline and both modes; app has passage voice assignment, variant selection, dictionary and normalization paths. |
| Voice conversion | RVC v2 file conversion, optional music separation/remix; live conversion for virtual audio devices; hotkeys and WAV recording | Offline STS API and live stream/session/recorder APIs and UI exist. Real-time is GPU-gated by default. |
| Edit Audio | Text-timed transcript edit/re-speak, filler removal, silence trimming with review, music ducking, speaker diarization, vocal/music separation, filters and WAV/MP3/FLAC/SRT export | Edit timeline/store and operation API include transcribe, diarize, separate, filter, convert, retext, speak, silence detection, ducking and render. This is more than a mock UI in source. |

**Emotion variants are reference clips, not automatic emotion recognition.** UI asks the user to add a short clip from the same speaker performed with a selected or custom emotion label; code stores that clip and its transcript as a TTS reference. F5-TTS then imitates the prosody in that reference. No automatic emotion classifier/detector was found. [Variant editor](https://github.com/XavierChuu/EasyVoice/blob/af299a5cce44c6f877047bff54496fc1a823c090/apps/desktop/src/features/voices/VariantEditor.tsx) · [voice service](https://github.com/XavierChuu/EasyVoice/blob/af299a5cce44c6f877047bff54496fc1a823c090/engine/easyvoice_engine/services/voices.py) · [user guide](https://github.com/XavierChuu/EasyVoice/blob/af299a5cce44c6f877047bff54496fc1a823c090/docs/marketing/guide/guide.html)

**Implemented versus planned:** At inspected `main`, major README workflows have corresponding engine and UI implementations. The source tree also contains `spikes/` benchmark scripts marked “not shipped”; these are research/prototype artifacts, not app features. `engine/README.md` labels Phase 1, 3, 4, 5 and packaging/runtime Phase 6 as present. This is source-level confirmation only; the README discloses Windows installer is unsigned, first run needs internet, and CPU is too slow for live conversion. Tests are mostly CPU/mock or synthetic/random-weight coverage per the engine README, so they do not establish real-world voice quality, latency, compatibility, or installer behavior. ## Integrated upstream projects and models

Model roles/licenses below follow EasyVoice's [`models.manifest.json`](https://github.com/XavierChuu/EasyVoice/blob/af299a5cce44c6f877047bff54496fc1a823c090/models.manifest.json) and [`NOTICE`](https://github.com/XavierChuu/EasyVoice/blob/af299a5cce44c6f877047bff54496fc1a823c090/NOTICE), then are cross-checked against first-party model/repository pages where available.

The README also states source/model/user-data are kept separately and models download on first launch.

## License summary and practical caveats

- **EasyVoice's own source:** current `main` `LICENSE`, README and `package.json` declare **GNU GPL-3.0-or-later**. The `v0.1.0` tag predates the addition of the `LICENSE` and `NOTICE` files; current `main` adds these but has no feature-code delta versus that tag. The GPL applies to EasyVoice's own source, not by itself to separately licensed models.
- **Bundled/vendored code:** RVC and rvc-python are separately identified as MIT in `NOTICE`; FFmpeg is identified as LGPL-2.1-or-later. Preserve their notices and satisfy their own distribution conditions. Vendored RVC's source commit is not recorded.
- **Weights:** there are 9 model entries / 18 files in the manifest. 17 of those files have `sha256: null` (only the ViVoice `.pt` has a recorded hash), so most downloads are not pinned to verified content by the committed manifest. The manifest comment says null hashes are filled after first download. This weakens reproducible provenance/integrity and makes license review less specific to immutable artifacts.
- **Commercial use:** F5-TTS v1 Base (CC-BY-NC-4.0) and ViVoice (CC-BY-NC-SA-4.0) are explicitly non-commercial; EasyVoice README says audio produced with them is also for personal/non-commercial use. Other model weights should be checked at their exact source revisions; source code being MIT does not settle weight terms. In particular, Demucs checkpoint and WavLM checkpoint have unresolved evidence above. User-provided voice data and rights/consent remain separate from software/model licenses.
- **Generated audio:** EasyVoice does not establish one universal output license. The README ties output restrictions to the selected TTS model. The rights to source/reference recordings, voice identity, datasets, and generated audio must be considered separately; the ViVoice card imposes its own non-commercial terms and use restrictions.

This is a repository-level license inventory, not legal advice or a full dependency SBOM. For redistribution/commercial deployment, resolve the two checkpoint uncertainties, record exact upstream revisions and hashes, and review transitive/bundled notices.
