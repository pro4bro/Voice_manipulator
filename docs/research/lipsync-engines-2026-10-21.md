# Lip-sync engine candidates for generated voice

Research date: 2026-10-21. Scope: offline video-to-video lip synchronization driven by an already generated voice WAV, with face replacement considered as a separate optional stage. This is a repository and license screen, not a benchmark run on project footage.

## Recommendation

Prototype **MuseTalk 1.5 first** as the local baseline: its official inference accepts video plus an audio file, has a documented Windows path, claims 30+ FPS on a Tesla V100 for its real-time path, and reports an 8-second clip taking about 5 minutes on an RTX 3050 Ti Laptop GPU in fp16. That makes it the clearest first integration candidate for this Windows, local-first product. It edits a 256×256 face region, so source-video identity is retained and it is not a face-swapper. Review quality on the actual Conviction source footage before choosing it: the speed/quality figures and examples are maintainer-reported, not independent measurements. [MuseTalk README](https://github.com/TMElyralab/MuseTalk), [MuseTalk report](https://arxiv.org/abs/2410.10122)

Keep **LatentSync 1.6** as a higher-detail comparison when the GPU has at least 18 GB VRAM; the authors specifically trained 512×512 inputs to reduce blurry lips/teeth. Its README documents image/video plus audio inference and adjustable quality/sync parameters, but warns that stronger sync guidance may introduce distortion/jitter. It is the stronger candidate to A/B for visual detail, with higher runtime cost and less comfortable fit to modest local GPUs. [LatentSync README](https://github.com/bytedance/LatentSync), [1.6 model card](https://huggingface.co/ByteDance/LatentSync-1.6)

**Do not select Wav2Lip's public weights for a commercial product.** It is still a useful research baseline and explicitly accepts any target speech/video, but its README restricts the public code/model/demo to personal, research, or academic use because of LRS2 training data. It also says its commercial Sync API model is materially higher quality; that is a separate hosted/licensed product, not the local open-source processor. [Wav2Lip README](https://github.com/Rudrabha/Wav2Lip)

For a more generative option, track **InfiniteTalk** separately: it claims video-to-video audio dubbing that adjusts head/body/expression as well as lips, and Apache-2.0 for the repository models. Its CUDA 12.1, Flash Attention, PyTorch 2.4.1 stack and Wan-family foundation make it a heavier pipeline than a targeted mouth-region editor; its own README describes demo/results, not a controlled quality comparison. It may be worth a later experiment when natural upper-body motion matters more than preserving every source frame. [InfiniteTalk README](https://github.com/MeiGen-AI/InfiniteTalk), [license](https://github.com/MeiGen-AI/InfiniteTalk/blob/main/LICENSE.txt)

## Face replacement is a separate operation

Lip-sync editors above generally change mouth motion on the source face; they do not replace the person's identity. Keep a separate optional face-replacement stage with its own source-face/target-face selection, preview, consent checks and license gate. [FaceFusion](https://github.com/facefusion/facefusion) is a maintained general face manipulation project with multiple face-swapper choices, but its repository license is OpenRAIL-AS and its model catalog itself marks some models (for example InsightFace `inswapper_128`) Non-Commercial and others with distinct terms. Therefore “FaceFusion supports it” does not clear every model for commercial use; license must be tracked per selected model and detector/recognizer. [FaceFusion license](https://github.com/facefusion/facefusion/blob/master/LICENSE.md), [model catalog](https://github.com/facefusion/facefusion/blob/master/facefusion/processors/modules/face_swapper/core.py)

## Suggested evaluation before choosing a processor

1. Run MuseTalk 1.5 and LatentSync 1.6 on the same short, consented project footage segments and the same generated voice, without altering original files.
2. Include frontal, slight-turn, glasses/facial-hair, low-light, fast speech, silence and scene-cut cases. Inspect frame-by-frame mouth/teeth artifacts and identity/background stability.
3. Record actual GPU/VRAM, cold-start and steady-state seconds per media second, output dimensions/FPS, audio duration, sync metric (e.g. SyncNet confidence) and human review. Do not infer quality from repository demos alone.
4. Before packaging, pin repo revisions and checkpoint hashes, preserve per-component license notices, and resolve weight/data rights independently of source-code licenses. In particular, do not package public Wav2Lip weights for commercial use without a separate grant.

## Unresolved

- No candidate has yet been run against the project's own footage or generated voice; quality/runtime ranking is a shortlist, not an acceptance result.
- MuseTalk's repository and HF card say MIT for code/weights, but downstream detector, pose, parsing and checkpoint assets need an itemized redistribution/commercial review.
- LatentSync's code Apache-2.0 does not automatically extend to its OpenRAIL++ model weights; legal/product owners should review the license text for intended use.
- InfiniteTalk's README claims Apache-2.0 model terms; confirm the exact release checkpoint and component/base-model terms before bundling.
- FaceFusion's available model licenses are heterogeneous and at least one popular swapper is explicitly non-commercial; the UI should expose only models with a recorded, reviewed license receipt.
